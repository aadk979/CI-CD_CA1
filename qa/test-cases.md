# Test Case Specification — TixQueue

Jira: **SCRUM-44**. Read with the [test plan](test-plan.md).

Each area starts with an **input analysis**: the equivalence classes and boundaries the cases were
derived from. The cases follow it. Every case traces to a Jira user story or task and names the
automated test(s) that run it in CI.

**Technique key:** **EP** equivalence partitioning · **BVA** boundary value analysis ·
**ST** state transition · **CON** concurrency · **EG** error guessing · **UC** use case (main path)

**Test file key:** `U:` `tests/unit/` · `I:` `tests/integration/` · `E:` `e2e/`. The quoted text is
the test's name, so `npx vitest run -t "<name>"` or `npx playwright test -g "<name>"` runs it.
Names with `%s`-style placeholders are parametrised tests: one test per row of input values.
